  <name>Task 1: Create LifecycleManager facade</name>
  <files>bidon/src/main/java/org/bidon/sdk/ads/cache/denis/lifecycle/LifecycleManager.kt</files>
  <action>
    Create LifecycleManager class that:

    1. **Instantiates lifecycle components:**
       - Creates AdInstanceScope (instance-scoped CoroutineScope)
       - Creates PeriodicSweepJob with the AdInstanceScope
       - Creates CancellationManager for auction cancellation

    2. **Provides lifecycle API:**
       - `start()` - Starts PeriodicSweepJob (call on cache() first use)
       - `stop()` - Stops PeriodicSweepJob and cancels AdInstanceScope (call on destroyAd())
       - `registerAuction(auctionId: String, job: Job)` - Delegates to CancellationManager
       - `cancelAuction(auctionId: String): Boolean` - Delegates to CancellationManager.cancelIfMatching()
       - `cancelCurrent(): Boolean` - Delegates to CancellationManager.cancelCurrent()
       - `getScope(): CoroutineScope` - Returns AdInstanceScope.scope for launching auction coroutines

    3. **Tracks started state:**
       - Boolean flag `isStarted` to prevent double-start
       - start() is idempotent (safe to call multiple times)
       - stop() clears started flag

    Package: `org.bidon.sdk.ads.cache.denis.lifecycle`

    Design rationale:
    - Facade pattern: single entry point for lifecycle management
    - Encapsulates lifecycle component wiring (AdInstanceScope -> PeriodicSweepJob dependency)
    - Prevents orphaned components: caller only needs to know LifecycleManager
    - Clear API: start/stop lifecycle, register/cancel auctions

    CRITICAL: This is NOT a singleton. Each ad instance (Interstitial/Rewarded/Banner) gets its own LifecycleManager.
    This aligns with Phase 4 decision: "Instance-scoped sweep jobs (each ad instance manages its own)".
  </action>
