  Fix two methods in AdCacheDenisImpl:

  **1. poll() - preserve V1 wait-until-ready semantics:**

  V1 poll() (from AdCacheImpl.kt) uses `results.first { it.isNotEmpty() }` which SUSPENDS until the Flow emits a non-empty list. V2 poll() currently calls pop() immediately and throws NoSuchElementException.

  User feedback: "сохрани v1" (preserve V1 behavior).

  Replace current poll() implementation with a suspending approach that waits for ReadyToShowCache to have an ad available. Since ReadyToShowCache is a singleton ConcurrentHashMap (not a Flow), implement a polling loop with delay:

  ```kotlin
  override suspend fun poll(): AuctionResult {
      // V1 semantics: suspend until cache has an ad
      while (true) {
          val result = pop()
          if (result != null) return result
          // Wait briefly before checking again
          kotlinx.coroutines.delay(100)
      }
  }
  ```

  This preserves V1 "wait-until-ready" semantics: the function suspends until an ad is available, then returns it. It cooperates with coroutine cancellation via the delay() checkpoint.

  **2. withSettings() - convert to NO-OP:**

  User feedback: "withSettings не должно сейчас применяться можно закомнтить" (withSettings should not be applied now, can comment it out).
